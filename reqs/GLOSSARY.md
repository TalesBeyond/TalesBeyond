# Hearthbound — Thesaurus

The project's ubiquitous-language reference: the terms the code, the docs
(`README.md`, `APP_OVERVIEW.md`, `SPEC.md`), and requirement plans under
`reqs/` all use for the same concepts. Use these terms exactly
when writing a REQ plan or touching the code they describe. A term a new
feature introduces gets added here as an implementation step in that
feature's own plan — this seed only records terms that already exist.

| Term | Definition | Notes |
| ---- | ---------- | ----- |
| Admin script | The local Node script (`scripts/catalog-admin.mjs`, `npm run catalog:seed`) the admin runs with the service-role key to load the Default catalog's rows and files into Supabase. Idempotent; the only writer of the catalog. | `scripts/catalog-admin.mjs` |
| Ambush | An entity kind that is the DM's own marker for a band of monsters lying in wait: it holds a list of monster drafts with a count each (`ambushMonsters`), shows the DM how many are waiting, and is never shown to players (same three-way enforcement as a Hidden token). "Reveal the ambush" on its inspector places every monster on the free squares around it, ring by ring outward, as ordinary monster tokens, and removes the marker. | `src/data/ambush.js`, `src/components/AmbushMonstersEditor.jsx`, `supabase/migrations/20250101000061_ambush_tokens.sql` |
| Atlas | The phone overview of every island on the current layer, with who is where; tapping an island flies to it. | `src/components/PhoneChrome.jsx` (`PhoneAtlas`) |
| Audio track | One MP3/WAV file attached to a target — the table (World music), a layer, an island, or a hero/mob token — with a name, synced Base volume and a Loop flag. One track per target; stored in `audio_tracks` and Storage (cloud), or only as a local blob URL in the DM's browser (guest tables, where nobody else hears it). The DM alone uploads, plays and pauses; only one plays at a time. | `src/lib/audioEngine.js`, `supabase/migrations/20250101000038_synced_table_audio.sql` |
| Base island | The permanent, undeletable first island in an island's `islandOrder` — where new players land on that layer. | `src/state/store.jsx` |
| Base layer | The permanent, undeletable first layer in `layerOrder[0]` — every table has one. | `src/state/store.jsx` |
| Bag | A hero's inventory: freeform gear/other-items lists plus bronze/silver/gold currency. | `src/components/RightPanel.jsx` |
| Base volume | The DM-set, table-wide volume (0–1) of an Audio track, synced to everyone. The audible level is Base volume × Local volume. | `src/components/MusicModal.jsx` |
| Catalog asset | One entry of the Default catalog: a weapon, item, monster, song or dice image, keyed by `slug`, with an optional file in a catalog bucket. | `src/lib/catalog.js`, `supabase/migrations/20250101000042_catalog_weapons.sql` |
| Catalog track | An Audio track whose file is a Default catalog song: its `url` is the catalog's public URL, `storagePath` is empty and `sizeBytes` is 0, so it uses none of the table's 50 MB and is never purged with the table. | `src/lib/audioEngine.js` (`isCatalogTrack`), `src/components/GameView.jsx` (`attachCatalogAudio`) |
| Character log | The DM-only list of what each player changed on their own hero this session: hit points, temporary hit points, bag items, coins, weapons and spells. Worked out on the DM's browser from the changes themselves, never stored, and gone when the DM reloads. Quick repeat edits to the same thing fold into one line. | `src/utils/heroActivity.js`; `CharacterLog` in `src/components/RollFeed.jsx`; toolbar button beside the Roll log, and Run table on phones |
| Chest | A lootable container entity kind with a size tier, an opened/closed state, and item contents. | `src/data/chests.js`, `supabase/11_chests.sql` |
| Clear drawings | The DM removing every drawing on the active island ("Clear this island") or on the current layer ("Clear this map"), after a confirm naming the count; undoable within the session. | `src/components/DrawingBar.jsx` (`DrawClearMenu`) |
| Cloud mode | The mode the app runs in when `VITE_SUPABASE_PROJECT_URL`/`VITE_SUPABASE_PUBLISHABLE_KEY` are set — actions go over the network through Supabase, live-synced via Realtime. | `src/lib/supabaseClient.js` |
| Day/night cycle | The four phases of the in-game day - Dawn, Day, Dusk, Night - derived from the Ingame clock and the DM's chosen sunrise and sunset; each island follows it, or is set to always day / always night, shown as a tint and a sun/moon badge. The DM can also set the phase by hand at any time (the toolbar's Day / night button, `dayNightOverride`), which takes priority over the clock until they choose "Follow the clock". | `src/utils/gameClock.js`, `src/data/dayPhases.js` |
| Compendium | A searchable catalog of weapons or items a host can buy/give directly into a hero's Bag. | `src/data/weapons.js`, `src/data/items.js` |
| Conditions | The fixed catalog of visual/informational status badges (Poisoned, Stunned, Prone, Shocked, Bleeding) toggleable on hero and mob tokens. | `src/data/conditions.js` |
| Connection grace period | The 1.5s window after a realtime channel drops during which the app stays silent, in case it's just a blip — only a drop that outlasts it surfaces the "Reconnecting…" scrim. | `src/components/GameView.jsx` |
| Default catalog | The read-only, admin-written set of weapons, items, monsters, songs and dice images that every table shares, stored in `catalog_*` tables and public `catalog-*` buckets. The app starts from the code data in `src/data` and swaps in the catalog's rows when Supabase returns them. Distinct from a table's own Custom assets. | `src/lib/catalog.js`, `supabase/README.md` |
| Dice model | A 3D model (.glb) of one die type in the Default catalog (`catalog_dice_models`). Groundwork for a later 3D-dice feature; nothing in the app renders it yet. | `supabase/migrations/20250101000047_catalog_dice_models.sql` |
| Dice skin | A texture image in the Default catalog (`catalog_dice_skins`) meant to be wrapped onto a Dice model, tied to one model or to a die type. Players choosing one is a later feature. | `supabase/migrations/20250101000047_catalog_dice_models.sql` |
| DM code | A guest table's private `session.hostKey`, shown only to its DM — required, alongside its exported file, to resume as host (checked as a hash, never stored in the file itself). | `src/state/store.jsx`, `src/components/Landing.jsx` (`GuestResumeForm`) |
| DM notes | Private, host-only free text on a hero or mob entity, never visible to other players. | `supabase/15_entity_dm_data_privacy.sql` |
| Door | A bidirectional portal entity kind linking two layers, with independently placed positions on each side. A player walks their own hero through by clicking it or landing on it; the DM dropping any hero or monster on a door gets the same "Open the door?" prompt for that token, and a hero's player follows it to the other layer. A door is fogged (Fog of war) only when both of its sides stand wholly in fog; with one side clear, players see it on that side only. A player cannot go through a door that comes out in a Held-back chunk. | `supabase/05_layers.sql`, `supabase/07_door_positions.sql` |
| Draw tool | The DM-only tool (`tool === 'draw'`) for marking up the map with Pencil, Line, Circle, Rectangle, Fill island, Select and Eraser. A press always draws, even on a token. | `src/components/MapBoard.jsx`, `src/components/GameView.jsx` |
| Drawing | One pencil stroke, line, circle or rectangle the DM drew on an island: `{ id, islandId, kind, geometry, style }`, geometry in grid squares from the island's top-left corner. Painted over the map art and grid, under every token; moves and is deleted with its island. Stored in `drawings` (cloud) or the table state. | `src/utils/drawing.js`, `supabase/migrations/20250101000052_drawings.sql` |
| Drawing bar | The Draw tool's controls: a column at the map's left edge on desktop (tools, style popover, Snap to grid, Undo, Redo, Clear), a two-row bar on phones with a "Drawing style" sheet. | `src/components/DrawingBar.jsx`, `src/components/DrawStyle.jsx` |
| Droppables | A mob's potential loot list, each item with a rollable drop-chance percentage. | `src/data/droppables.js`, `src/components/DroppablesEditor.jsx` |
| Enemy sheet | A monster's DM-only version of a hero's six-tab character sheet (Overview, Abilities, Saves & Skills, Battle Equipment, Spells, Bag), kept in `mobSheet`. Players only ever see a monster's name, AC, HP, size, and conditions; its Battle Equipment attacks heroes. Stored in `entity_dm_data` (host-only RLS) in cloud mode and stripped from guest broadcasts. | `src/components/RightPanel.jsx` (`MobInspector`), `supabase/migrations/20250101000030_mob_sheet.sql` |
| Entity | Any placeable thing on the map — a hero, mob, door, or chest — keyed by id, carrying a `layerId`/`islandId` and kind-specific fields. | `src/state/store.jsx` |
| Feet per square | How many feet one grid square stands for — each island's own (`island.feetPerSquare`), set in Mapping → Islands → New island (default 5) or the island's Settings. Islands from before fall back to their layer's value. Drives the ruler, movement range and drawing labels on that island. | `src/utils/grid.js` (`islandFeet`), `supabase/migrations/20250101000054_island_feet_per_square.sql` |
| Fill island | The Draw tool that paints a whole island one colour (with an opacity), over the map art and under the grid — a drawing of kind `fill`. Clicking a filled island recolours it; the same colour again clears it. | `src/components/MapBoard.jsx` (`fillIsland`), `src/utils/drawing.js` |
| Fly to island | On a phone: make an island the active island, set the zoom that fits it on screen, and centre it. | `src/components/GameView.jsx` (`flyToIsland`) |
| Fog chunk | One rectangle of Fog of war on one island: `{ id, islandId, x, y, w, h, revealed, revealOnEnter }`, in whole grid squares from the island's top-left corner. Squares outside the island's current size are ignored, and an island resize never rewrites the stored rectangle. Only the DM lays, moves, resizes, reveals, fogs again or deletes one. It moves with its island and is deleted with it. | `src/utils/fogOfWar.js`, `supabase/migrations/20250101000068_fog_chunks.sql` |
| Fog of war | The DM's tool for covering parts of a map until the party explores them. A square is fogged while at least one unrevealed Fog chunk covers it: players see an opaque cover there, the DM a tint (and, once a chunk is revealed, a dashed outline with a corner tag). A token that is not a hero and stands wholly on fogged squares is fogged (`entities.fogged`, written only by the DM's client) and does not exist for players, like a Hidden token. Revealing is for the whole table; there is no per-player fog. Not the Fog Island condition. | `src/utils/fogOfWar.js`, `src/components/FogOfWarLayer.jsx`, `supabase/migrations/20250101000069_fogged_tokens.sql` |
| Guest channel | The Supabase Realtime Broadcast channel (`guest:<code>`) a guest table's live sync runs on in place of `postgres_changes` — carries `state_change`, `intent`, `player_join`, and `state_request`/`state_snapshot` messages. A player asks for a snapshot every time their channel connects (a reload too) and again when the host appears. | `src/lib/guestRealtime.js` |
| Guest table | A table its DM opened with no account and no row in any Supabase table — live sync runs over a Guest channel with the DM's own browser as the sole source of truth; never written to Postgres. | `src/components/Landing.jsx` (`GuestHostForm`), `src/components/GameView.jsx` |
| Held-back chunk | An unrevealed Fog chunk with "Reveals when entered" off. It opens only by the DM's hand, and a player cannot move their own hero onto any of its squares, by drag, phone tap, planned move or door: the hero stays where it was and the log says the area is not open yet. A hero already inside can walk out. Checked by the player's own client on cloud and local tables and by the DM's client on a guest table (the database does not check it); the DM is never restricted. A chunk laid over a hero starts held back, and "Fog again" on a chunk a hero stands in makes it one. | `src/utils/fogOfWar.js` (`isHeldBackDestination`), `src/components/GameView.jsx` |
| Hide drawings | A per-browser switch, for anyone at the table, that hides the DM's drawings here only (`hearthbound:drawprefs`). | `src/components/Toolbar.jsx`, `src/components/PhoneChrome.jsx` |
| Hidden token | A monster, chest or door the DM has ticked "Hidden from players" on (`hidden`). It doesn't exist on any player's map until the DM shows it again; the DM sees it ghosted. Enforced the same three ways as an unrevealed Trap: an `entities` RLS rule in cloud mode (hiding is followed by a `conceal` broadcast, since Realtime sends nothing when a row stops being readable), the DM's broadcast filter in a guest table, and a client filter in local mode. A token standing wholly in the Fog of war (`fogged`) is kept from players the same three ways; that flag is worked out by the DM's client, never ticked, and a trap can carry it too. | `src/data/visibility.js`, `supabase/migrations/20250101000059_hidden_tokens_locked_doors.sql`, `supabase/migrations/20250101000069_fogged_tokens.sql` |
| Hint | A short note under a control that can't be used yet: why, then where to fix it, with the fix as a button when it's one step. Always shown, whatever Show hints and tips says. | `src/components/Hints.jsx` (`Hint`) |
| Host | The one player per table with `isHost: true` — the DM, who can edit everything. | `src/state/store.jsx` |
| Host account | A host's permanent email/password Supabase identity (cloud mode) — lets them sign in from any device and see/resume every table they've created, unlike the anonymous session it replaced. | `src/lib/auth.js` (`signUpHost`/`signInHost`), `src/components/Landing.jsx` |
| Host key | A second, private code shown only to the host, usable in local mode to re-seat someone as host of a table saved in that browser. | `src/components/Landing.jsx` |
| Hero | An entity kind representing a player character, carrying a full 5e character sheet and an `ownerId`. | `supabase/08_character_sheets.sql` |
| Ingame clock | The table's single in-game time ("2:30 PM, Day 3"), set and edited by the DM from the toolbar's "Ingame time" modal and shown to everyone. Stored as an anchor plus a Tick, so each client works out the current time itself. | `src/utils/gameClock.js`, `src/components/ClockModal.jsx`, `supabase/migrations/20250101000032_game_clock.sql` |
| Intent | A guest player's proposed action (e.g. a token move), sent over the Guest channel for the DM to validate and apply rather than dispatched locally — only the DM's browser is authoritative. | `src/lib/guestRealtime.js`, `src/components/GameView.jsx` |
| Invite code | The short code players use to join a table; can be regenerated (invalidating the old one) by the host. | `supabase/03_functions.sql` |
| Island | A freeform grid within a layer — its own size, cell size, and background image, positioned relative to other islands. Always its own independent rectangle — never combined with another island's shape. | `supabase/10_islands.sql` |
| Island chip | One island in the phone island strip under the top bar: its name, size or group, and how many tokens are on it. | `src/components/PhoneChrome.jsx` (`PhoneIslandStrip`) |
| Island condition | A visual/informational state the host can set on an island - Fog, Darkness, Fire, Unstable footing, Drowning, Icy, Poison gas, Storm, Difficult terrain, Cursed - shown to everyone as icon badges on the island's top edge (the map-level twin of a token's Conditions). Set per island in Mapping → Islands; an island in a group takes its group's conditions instead (badges on the group's box), and gets its own back when ungrouped. Not enforced mechanics. | `src/data/islandConditions.js`, `supabase/migrations/20250101000031_island_conditions.sql` |
| Island group | A set of 2+ islands on the same layer bundled by the host via "Group Islands" — moved together via an invisible bounding box and shown under one shared title instead of each member's own label; each island keeps its own grid, background, and size. The group carries its own Island conditions (`group.conditions`), which stand for every member; it starts with every condition its islands had. | `layer.islandGroups`, `src/components/MapBoard.jsx` |
| Island view | The phone game screen: the map framed on one island at a time, titled by that island. | `src/components/PhoneChrome.jsx` |
| Keep-awake | The Screen Wake Lock a guest table hosted from a phone holds while the page is visible. | `src/components/GameView.jsx` |
| Kick | The DM removing another player's seat from the table (Players dropdown on desktop, Party sheet on phones), after a confirm. The kicked player lands back on the landing screen with a notice; their heroes stay on the map with no one playing them. The player code is refreshed right after, so the code they joined with stops working while everyone still seated carries on. | `kickPlayer` in `src/components/GameView.jsx`; cloud mode needs `20250101000056_host_kick_player.sql` |
| Layer | A separate map/level within a table, holding any number of islands and linked to other layers by doors. | `supabase/05_layers.sql` |
| Local demo mode | The mode the app runs in by default — the whole table lives in `localStorage`, no server involved. | `src/state/persistence.js` |
| Locked door | A door the DM has ticked "Locked" on (`locked`). Players still see it, with a padlock, but can't click it or walk through it until the DM unlocks it; only the DM can change the flag (a trigger enforces that in cloud mode). A chest can be locked the same way (the lock icon on its card): players still see and inspect it, with a padlock, but can't open it (an unlocked chest they open themselves); locking shuts it and the DM opening it unlocks it. | `src/data/visibility.js`, `src/components/MapBoard.jsx`, `supabase/migrations/20250101000059_hidden_tokens_locked_doors.sql`, `supabase/migrations/20250101000065_locked_chests.sql`, `supabase/migrations/20250101000066_players_open_chests.sql` |
| Loot (monster) | What a defeated monster actually dropped: when its hit points reach 0, the DM's client rolls its Droppables once and writes the result onto the token (`loot`), where everyone can see it. Never re-rolled, even if the monster is healed and falls again. | `src/data/droppables.js` (`rollDroppables`), `src/components/RightPanel.jsx` (`MobLoot`), `supabase/migrations/20250101000063_monster_loot.sql` |
